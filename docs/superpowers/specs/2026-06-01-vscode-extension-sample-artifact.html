HTML Review Kit VS Code Extension

This sample design spec describes a VS Code extension that lets developers review generated HTML artifacts, export HTML Review Kit comment packets, and hand those packets to coding agents without leaving the editor.

Status Sample draft for review
Owner HTML Review Kit maintainers
Date 2026-06-01
Scope VS Code local workflow

Summary

The extension provides a first-party editor workflow for HTML Review Kit. A developer can open an HTML artifact in a VS Code webview, add comments anchored with data-hrk-id, export .review/html-review-comments.json, and ask a coding agent to apply those comments to the source file.

The extension is intentionally local-first. It does not host collaboration sessions, manage accounts, or patch source files directly in the first release.

Goals And Non-Goals

Goals

  • Preview local HTML artifacts in a secure VS Code webview.
  • Enable comment mode with the same packet shape as @html-review-kit/core.
  • Write review packets to .review/html-review-comments.json.
  • Surface a copyable agent instruction for Codex, Claude Code, and generic agents.
  • Keep exported comments portable across CLI, browser, and React workflows.

Non-Goals

  • No hosted review backend or realtime multiplayer review.
  • No automatic source patching inside the extension.
  • No dependency on React in the core review runtime.
  • No screenshot comparison or visual diff engine in v0.

User Experience

  1. Developer runs HTML Review Kit: Open Artifact from the command palette.
  2. The extension asks for an HTML file and opens it in a webview review surface.
  3. The developer clicks elements or selects text to create anchored review comments.
  4. The sidebar lists open and resolved comments with target summaries.
  5. The developer exports the packet into the workspace .review directory.
  6. The developer sends the packet to an agent using the generated instruction snippet.
The webview must preserve semantic page behavior where possible. Review controls should avoid blocking scrolling, keyboard navigation, or normal text selection outside comment mode.

Architecture

Extension Host

Registers commands, reads workspace files, writes review packets, validates packet shape, and passes trusted artifact metadata into the webview.

Review Webview

Renders the selected HTML artifact and runs @html-review-kit/core in the webview document. It posts comment state changes back to the extension host.

Packet Adapter

Normalizes artifact metadata, resolves the source file path, and writes exported comments to the same JSON packet format used by the SDK and AI skill.

Commands

  • htmlReviewKit.openArtifact: open a selected HTML file in review mode.
  • htmlReviewKit.exportComments: write the current packet to disk.
  • htmlReviewKit.importComments: load an existing review packet.
  • htmlReviewKit.copyAgentPrompt: copy agent handoff instructions.
  • htmlReviewKit.validatePacket: validate the current packet schema.

Data Flow

workspace HTML file
  -> VS Code extension command
  -> webview HTML renderer
  -> @html-review-kit/core review layer
  -> postMessage(comment changes)
  -> extension host packet adapter
  -> .review/html-review-comments.json

The exported packet includes artifact id, title, source file, schema version, comments, targets, timestamps, and optional agent instructions. Comments retain all available target anchors so agents can resolve edits in a stable order.

Security And Constraints

  • Use a restrictive webview content security policy.
  • Disable arbitrary remote network access from the review surface.
  • Load local assets through VS Code webview URIs.
  • Do not execute inline scripts from the reviewed artifact unless explicitly enabled.
  • Keep generated packets inside the active workspace unless the user chooses another path.

Testing Strategy

  • Unit test packet creation, validation, and path normalization.
  • Unit test command registration and failure paths with VS Code test utilities.
  • Webview integration test comment creation, export, import, and target preservation.
  • Fixture test sample HTML artifacts with and without existing data-hrk-id anchors.
  • Manual smoke test command palette workflows in a local extension host.

Milestones

M1

Extension Scaffold

Add a VS Code extension package, command registration, build scripts, and local extension host smoke test.

M2

Review Webview

Render local HTML in a webview and initialize @html-review-kit/core with artifact metadata.

M3

Packet Export

Write .review/html-review-comments.json, validate it, and expose agent handoff instructions.

M4

Polish And Packaging

Add import support, error states, documentation, extension marketplace metadata, and release validation.

Open Questions

  • Should the extension support reviewing generated HTML strings from unsaved editor tabs?
  • Should packet export overwrite by default or create timestamped review packet variants?
  • Should the first release ship as a package in this monorepo or as a separate repository?
